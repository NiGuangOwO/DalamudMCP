## 简体中文

- 修复兵装库转移路径：1.0.0.54 直接调用 `InventoryManager.MoveItemSlot` 虽然通过客户端库存读回，现场随后出现穿戴或最强功能显示其他部位/职业的装备。现在通过已观测的 `AgentInventoryContext.OpenForItemSlot` 打开准确物品的原生右键菜单，精确匹配当前语言的“放入兵装库”，调用唯一注册的原生列表处理程序，由游戏选择实际空位，不再直接调用移动 API。
- 菜单目标、HQ、数量、文字、行索引、注册监听器、启用状态和布局均受检查；选择行后、发送业务事件前再次校验来源。支持库存菜单内嵌监听器，同时保持普通列表工具的原有归属限制。默认预检不打开菜单；已有菜单时拒绝。确认要求原先为空的实际目标槽位匹配完整物品属性并稳定至少 250ms，返回 `confirmationScope=nativeMenuAndClientInventory`。增加 `open_addon` / `close_addon` 的 `character` 角色界面入口，并同步文档、Skill 与 CI 回归。
- 验证：Debug/Release 均为 0 警告、0 错误；原生 UI 回归 268/268，装备转移检查 49/49，插件加载 256/256，协议 89/89，指引目录 22/22、Python 技能同步 23 项及发布流程 13 项通过。
- 国服客户端连接本机 Kawari 测试服现场：通过原生菜单累计转移 123 件装备，其中 30 件 HQ；最后四个主背包为 0 件。每次均检查物品总量和穿戴装备不变。用户对新路径转入的两件治愈装备进行下游对照，并确认已恢复正常；未将原来的库存读回等同于穿戴/最强功能成功。临时观察器已清理。
- 限制：未完整定位旧路径下所有客户端/服务端内部原因；本次采用经过对照验证的原生菜单路径。下游确认覆盖上述两件治愈装备，并非每件物品、每个职业的全量穿戴/最强验证。国际服和官方服务器未现场验证；魂晶没有现场转移；满仓、来源变化、布局变化与失效监听器主要由离线用例覆盖。超时不重试，已发出而未确认的操作继续阻止提交；主机重载会清空会话记录，重连后需重新检查库存。

## English

- Fixes the armoury transfer path. The direct `InventoryManager.MoveItemSlot` path in 1.0.0.54 passed client inventory readback, but subsequent live equip/recommendation checks displayed items for other slots/jobs. Transfers now open the exact item's native context menu through the observed `AgentInventoryContext.OpenForItemSlot` contract, match the current localized Store in Armoury Chest label, and invoke its uniquely registered native list handler. The game chooses the actual empty slot; the tool no longer calls the move API directly.
- Guards the menu target, HQ, quantity, text, row index, registered listener, enabled state and layout. Rechecks the source after row selection and immediately before the business event. Supports the inventory popup's embedded listener while retaining the ordinary list tool's ownership restrictions. Default dry-run does not open UI; existing menus are refused. Confirmation requires a previously empty actual destination to match complete item attributes for at least 250ms and reports `confirmationScope=nativeMenuAndClientInventory`. Adds `character` to `open_addon` / `close_addon`, and updates documentation, the Skill and CI regressions.
- Validation: Debug/Release builds each completed with zero warnings/errors. Native UI checks passed 268/268, transfer checks 49/49, plugin-load checks 256/256, protocol checks 89/89, guidance catalog 22/22, Python skill synchronization 23 tests and release pipeline 13 tests.
- Live CN client connected to the local Kawari test server: 123 native-menu transfers, including 30 HQ items, ended with all four carried bags empty. Each transfer checked item quantity conservation and unchanged equipped items. The user performed a downstream comparison on two healer items moved through the new path and confirmed normal behavior. The old inventory readback was not treated as proof of equip/recommendation success. Temporary observers were removed.
- Limitations: the complete client/server internals responsible for the old path were not established; this fix uses the native menu path validated by the comparison. Downstream confirmation covers those two healer items rather than every item/job/equip/recommendation combination. Global and official servers were not tested live; no soul crystal transfer was performed. Full storage, changed sources/layout and invalid listeners mainly have offline coverage. Timeouts do not retry; dispatched unconfirmed operations block further submissions. Host reload clears session records, so inspect inventory after reconnecting.
