## 简体中文

- 新增只读 `get_armoury_inventory`：返回兵装库各部位的实时容量、已用/空位、物品，以及四个主背包中装备对应的兵装库分类。不可用容器保持未知；部位依据当前客户端装备槽位数据解析。
- 新增 `move_inventory_item_to_armoury`：通过原生 `InventoryManager.MoveItemSlot` 将一件已核对的背包装备放入对应分类空格。必须提供物理容器、槽位和包含 HQ 编码的预期物品 ID；默认仅预检。检查变更权限、角色空闲、实时容器、物品身份、数量与空位，串行提交；最多等待 3 秒，来源为空且目标物品及保存属性一致并稳定至少 250ms 才确认。未确认请求阻止继续提交，直到读回确认或角色改变；不自动重试。同步更新工具参考、Skill 与持续集成检查。
- 验证：Debug/Release 构建均为 0 警告、0 错误；两个构建的装备转移检查均为 49/49，加载检查均为 256/256；协议 89/89、指引目录 22/22、Python 技能同步 23 项和发布流程 13 项通过。
- 国服现场：核对运行构建 MVID 后，预检未改变库存；先转移一件，再逐件完成剩余 123 件，总计 124 件、其中 30 件 HQ，覆盖主副手、防具和首饰共 11 类。四个主背包最终为 0 件；每件转移均有稳定库存读回，逐次检查物品总量守恒和已穿戴装备不变。空来源的实际提交被拒绝，库存未变。
- 限制：只支持四个主背包到匹配兵装库空格的单向转移，不交换、不丢弃、不装备。魂晶已验证读取和离线分类，未现场转移；满仓、不可用容器和物品变化由离线用例覆盖。超时/并发保护未做客户端故障注入，未现场切换角色或全局变更权限。主机重载会清空会话中的未确认记录，重连后应重新检查库存。国际服及其他客户端版本未现场验证。

## English

- Adds read-only `get_armoury_inventory`, reporting live per-category armoury capacity, used/empty slots, stored items and the matching armoury category for equipment in all four carried bags. Unavailable storage remains unknown; destinations follow the current client's equipment-slot data.
- Adds `move_inventory_item_to_armoury`, using native `InventoryManager.MoveItemSlot` to place one verified carried equipment item in an empty matching category slot. Requires the physical container, slot and expected quality-encoded item ID; dry-run is the default. Checks mutation access, idle state, live storage, item identity, quantity and free space, and serializes submissions. Confirmation requires an empty source and matching destination item/stored attributes stable for at least 250ms, within a 3-second wait. Unconfirmed requests block further submissions until readback confirms them or the character changes; there are no automatic retries. Updates tool references, the Skill and CI checks.
- Validation: Debug and Release builds each completed with zero warnings/errors; transfer checks passed 49/49 and plugin-load checks 256/256 for both builds. Protocol checks passed 89/89, guidance catalog 22/22, Python skill synchronization 23 tests and release pipeline 13 tests.
- Live CN validation: after verifying the running build MVID, dry-run left inventory unchanged. One initial transfer followed by 123 individually confirmed moves transferred all 124 items, including 30 HQ items, across 11 weapon, offhand, armour and accessory categories. All four carried bags ended empty. Each move had stable inventory readback, with item quantities conserved and equipped items unchanged after every transfer. An actual empty-source submission was refused without changing inventory.
- Limitations: only one-way moves from the four carried bags to empty matching armoury slots are supported; no swaps, discards or equipping. Soul crystals had read and offline classification coverage but no live transfer. Full/unavailable storage and changed items have offline coverage. Timeout/concurrency protections were not fault-injected in the client; character switching and the global mutation gate were not changed live. Host reload clears session-local unconfirmed records, so inspect inventory after reconnecting. Global and other client versions were not validated live.
