# Choose tools by the question

For `SelectString`, prefer `select_addon_menu_item` by label and inspect `dryRun` first. Its `indexKind=menuOrdinal` is a zero-based popup entry index, not the label's `AtkValue` index. Other addon layouts retain legacy callback behavior and need an independently established contract; a text-field index alone is insufficient. See [menu-selection.md](../../../../docs/menu-selection.md).

String-keyed IPC queries support `Func<string, bool>`, `Func<string, bool?>` and `Func<string, string>` with a strict bounded JSON string `value`. Preserve a nullable result as unknown. Check competing automation through its provider contract before attributing a live result to the plugin under test; querying does not authorize changing the provider's configuration.

Use the connected schemas for exact arguments, limits and defaults. This is a routing guide, not a complete tool catalog. Server aliases and tool namespace prefixes may differ between clients.

| Question | Useful tools and interpretation |
| --- | --- |
| Is the client ready for this test? | `get_client_state`, `get_local_player`, `get_conditions`; read the returned loading/occupied state before interacting. |
| Where is the character, and how do I get somewhere? | `get_position` is the cheap transform read (x/y/z, rotation, compass bearing, zone, `inCombat`/`mounted`/`betweenAreas`, optional distance to one object) — use it instead of the heavy `get_local_player` when only navigation state matters. Movement is vnavmesh-backed: `move_to_position` for raw coordinates, `move_to_entity`/`move_to_nearby_targetable_object` for objects, `stop_movement` to cancel. Confirm with a follow-up `get_position` instead of trusting the dispatch; `stop_movement` returns `available=false` plus the probed entry points when no stop gate exists, which means the walk may continue. |
| Which ability or gearset applies right now? | `get_cooldowns` includes inherited class and role actions at effective level, and distinguishes `remainingSeconds` (until a charge is available), `nextChargeInSeconds`, `fullRechargeSeconds` and `cooldownReady`. GCD-only actions are excluded; partial charges can still be ready. `get_gearsets` scans all 100 slots for sparse Exists entries; active `equipmentMatches` compares item IDs/HQ. `equip_gearset` accepts strict integer IDs or unique names, always reapplies even the active set, and confirms index/job/item IDs. It does not verify dyes, glamour or materia. See [state and confirmation](../../../../docs/ability-gearset-state.md). `execute_action` defaults to the hard target and reports refusal status. |
| How do I find a plugin feature without its source? | `plugin_list` / `plugin_describe`, then `list_plugin_commands` to read registered command help (including hidden-help entries), or `open_plugin_ui` for one exact loaded plugin's supported UI. Discover subcommands through runtime help/UI before invoking them. Handler assembly is only a routing hint; shared wrappers can obscure ownership. Inspect resulting native/ImGui state after requesting UI. Follow project restrictions on target-plugin source access. |
| Which tribal quests should I prioritize? | `get_tribal_quest_state` reads actual remaining allowance, reputation/max rank and the day's quest ledger. Quota errors and unknown ranks stay unknown. Confirm offered quests in live NPC UI; completed-once flags do not mean a repeatable daily is unavailable today. The quest sheet row ID and a plugin's short quest ID can differ; use the plugin's displayed IDs. |
| Which nearby object is relevant? | `get_game_objects`, `find_game_object`; resolve live object identity rather than reuse an address from a previous process, zone or object lifetime. |
| What does a row, status or action mean? | `search_game_data`, `get_game_data_row`, `get_item`, `get_action`, `get_status`; use the installed client's localized data. |
| Where does the player hold an item? | `search_item_holdings` accepts exactly one base `itemId` or localized `name`. Covers bags/crystals, equipment, armoury, normal/premium saddlebags and visited retainers. Read `coverage`, `retainers`, `source`, timestamps and `complete`; unloaded/unvisited storage is unknown, not zero. Retainer live reads require its visible, ready inventory UI; closed storage uses a session snapshot, even if native containers remain loaded. Snapshots are cleared on logout/reload. `includeCached=false` restricts to live data. See [item-holdings.md](../../../../docs/item-holdings.md). |
| Which native game window is present? | `list_loaded_addons`, then `get_addon_state` or `get_addon_strings`. Discovery returns exact addon names; it does not expand `open_addon`'s allowlist. Read each tool's supported inputs. |
| How do I open or close the bag window? | Use `open_addon` / `close_addon` with `addon="inventory"`. This uses the dedicated UI-module API, reports actual `open`/`observed`, and is idempotent. The persistent inventory agent being active is not proof of an open bag. `get_addon_state` uses the bag-window state and lists unavailable inventory state in `unknown`. Confirm loaded Inventory/InventoryLarge/InventoryExpansion windows before touching slots. See [inventory-ui.md](../../../../docs/inventory-ui.md). |
| How do I open a carried item's context menu? | Discover an allowed inventory-grid DragDrop node, then `open_addon_context_menu` with `dryRun` first. This sends one registered right-button event, not all registered events. Inspect the resulting ContextMenu and `get_inventory_context`, then match its container/slot with `get_inventory`. UI ordering and physical bag slots differ; never infer the item from node id/reference index. Select only a discovered menu entry after verifying the actual item. See [inventory-context-menu.md](../../../../docs/inventory-context-menu.md). |
| Which node changes, and when? | Use `list_addon_elements` with `label`/`componentType`/state filters and `detail="compact"` for ordinary lookup; use full detail for geometry/debugging. Copy the returned `componentPath` and `nodeId` to `get_addon_node_snapshot` (as `nodeIds`) or `sample_addon_nodes`. IDs repeat across components; paths resolve exact ULD scopes. `truncated`/`scanIncomplete` prevent conclusions about absence or uniqueness. |
| Which event corresponds to normal interaction? | Use observed node events or a narrowly scoped `probe_receive_event_enable` / `probe_callback_enable`, inspect `probe_receive_event_dump` / `probe_callback_dump`, and remove with `probe_receive_event_disable` / `probe_callback_disable`. A listener hook has its own `probe_receive_event_enable_listener`; consult its schema and limit observation to the relevant addon. |
| How to perform a known UI interaction? | `click_addon_element`, `select_addon_menu_item`, or `click_addon_when_node_matches` as appropriate. For `click_addon_element`, copy `nodeId` and `componentPath` from discovery; do not also pass `componentId`. Re-query after addon replacement: a path is not a lifetime token. Confirm visibility/enabled state, addon identity and current phase. Raw `fire_addon_callback` needs an established argument contract, not guessed indices. Verify the transition afterward. |
| How do I enter text in a native game field? | Discover `componentType="TextInput"`, then `set_addon_text_input` with exact `nodeId`/`componentPath`, `dryRun` first and optional `expectedText`/`expectedAddonId`. Text is single-line plain UTF-8, at most 256 bytes. Inspect actual `text` and `exactMatch`; native filtering can alter it. It does not submit or send Enter. Discover and click the real search button separately; `imgui_text` only targets Dear ImGui. Hidden ancestor panels are refused even if a child's own visible flag is set. See [native-text-input.md](../../../../docs/native-text-input.md). |
| How do I change a native number field? | Discover `componentType="NumericInput"`, then `set_addon_numeric_input` with a strict integer `value` and `dryRun` first. Read live `min`/`max`; out-of-range values are refused. Guard prior state with `expectedValue`/`expectedAddonId`, inspect actual `value`/`exactMatch`, and verify the UI. It does not press Enter or confirm the surrounding dialog. See [native-numeric-input.md](../../../../docs/native-numeric-input.md). |
| Which map and icons am I looking at? | `get_map_state` distinguishes current/selected map IDs and pages static markers. Check `mapVisible/mapReady` and recheck selected map between pages. Raw native marker X/Y are not world/movement coordinates. This is not a complete dynamic-marker list. See [map-state.md](../../../../docs/map-state.md). |
| How do I use a native dropdown? | Discover `DropDownList` node/path, read indexed options with `get_addon_dropdown`, use `set_addon_dropdown_open`, and wait for open/settled/visible state. Then `select_addon_dropdown_item` requires the exact observed label and supports old-index guards/dry run. Native selected text alone is insufficient: verify actual addon behavior. See [native-dropdown.md](../../../../docs/native-dropdown.md). |
| How do I activate a native List/TreeList row? | Find its text/component path, query the owning renderer with `get_addon_list_row`, then use `activate_addon_list_row` with exact actual-index/text guards. Renderer node IDs and AtkValue indices are not row indices. Preview first, wait for actual outcome, and avoid automatic repeat activation. See [native-list-rows.md](../../../../docs/native-list-rows.md). |
| How do I distinguish image-only UI symbols? | `get_addon_node_snapshot`/`sample_addon_nodes` return guarded `image` atlas-part/UV and typed asset metadata for Image nodes. Local part/asset IDs are not text or global icon IDs; calibrate from actual current UI and preserve unknowns. See [native-image-parts.md](../../../../docs/native-image-parts.md). |
| Is an input tied to moving geometry? | `sample_addon_nodes`, then `click_addon_when_node_matches` with geometry/state guards in the same frame. Prefer native screen transforms to summing local coordinates. A one-event conditional click is not an atomic press/hold/release controller; handle timeout and cleanup without releasing into a replacement addon. |
| Is the new plugin build running? | `load_dev_plugin` checks the loaded DLL's MVID, not just its name; `plugin_list` / `plugin_describe` inspect lifecycle state. MCP cannot load itself through that tool. |
| Can an existing plugin expose the needed value? | `list_ipc_endpoints`, then `call_plugin_ipc` if the endpoint contract is suitable. Calls are mutating-gated even when their signature returns a value; read the provider's semantics. Integers and booleans must use native JSON types. |
| What changed without polling full state repeatedly? | `query_events`, `events_wait`; pass the returned `lastId` as the next `afterId`. `plugin_data_subscribe` / `plugin_data_poll` / `plugin_data_unsubscribe` cover supported plugin data subscriptions. Empty results or a dropped event history are not proof that no game transition occurred. |
| What did Dalamud or a plugin log? | `get_dalamud_log` reads runtime diagnostics, including while logged out; `get_chat_log` is game chat. Poll using `streamId` and `nextAfterId` as `afterId`, drain `hasMore`, and check `available`, `historyLost`, and entry `truncated`. Only logs since plugin load at Dalamud's configured level are captured; no file backfill. See [runtime logs](../../../../docs/dalamud-logs.md). |
| What actions happened during each combat encounter? | Background recording defaults on while the mutation gate permits and continues without MCP clients/listener. `combat_recording_configure` persists enable/disable; `combat_recording_status`, `combat_recording_list`, `combat_recording_read` and `combat_recording_export` inspect/export. Completed fights are compressed automatically; read can fall back to archives after reload. Check archive errors, truncation, partial-start and packet-loss metadata. This is not a complete FFLogs parser; see [combat-recording.md](../../../../docs/combat-recording.md). |
| Is a typed API insufficient? | `get_module_info`, `query_memory_region`, `read_memory`, `read_pointer_chain`, `read_object_memory`, `scan_signature`; first read the native-debugging reference. |
| Is an actual picture needed? | `capture_game_screenshot` with `imageContent=true` returns a native MCP image; default `area=client` copies the game render target, not the desktop. Minimized capture can succeed while rendering continues. Use `includeDalamudUi=false` to exclude plugin overlays. Cached fallback requires `allowCached=true`; inspect `cached`, `ageMs` and `capturedAtUtc`. `save=true,includeImage=false` avoids transmitting pixels. |
| Must the game's window be minimized/restored? | `set_game_window_state` is a separate mutating-gated action, usable without login. Use only within the task's authorization; verify `observed`. Screenshots never restore/focus the window automatically. |

For automatic click parameters, exact registered zero is valid. Discover the actual event type; missing-type legacy fallback is not proof that the requested event applies. Conflicting exact parameters refuse input. See [native-click-parameters.md](../../../../docs/native-click-parameters.md).

`imgui_*` targets Dear ImGui input/windows; it is not the native Atk addon tree. Use native addon tools for node identity and event contracts. Respect any user prohibition on visual input or computer use; having an input tool does not override it.
Native node `visible` includes addon, ancestor and component-scope visibility. Full queries and snapshots expose `selfVisible` separately. `visible=null` means ancestry is unreadable/cyclic/over budget; filtered queries exclude it and set `scanIncomplete`. Visibility is not an occlusion or hit-test guarantee.
`visibleOnly` prunes known-hidden component subtrees; completeness then applies to visible results, not the entire hidden tree. Root ULD discovery supports dynamic lists above 512 entries within the same 4096-node total budget. See [addon queries](../../../../docs/addon-queries.md).

Tool responses describing a command/event dispatch are intermediate evidence. For example, follow a duty-list selection with a fresh list/state read; do not treat `fired=true` as proof of a selected duty or queue registration. Missing windows, an unavailable action and an idle cancellation are valid contextual outcomes, not successful gameplay tests.
`click_addon_when_node_matches` also supports `matchAxis="rotation"` with inclusive `minRotation`/`maxRotation` in local radians (-pi to pi, no wraparound). This is separate from screen-position matching; omit targetNodeId and width bounds. Use same-frame phase guards and verify resulting game state.
Use `slash_command` for slash commands. `send_chat` is channel-prefixed ordinary speech and rejects leading-slash text; do not try to bypass this guard. Rejected command text is not executed.
For native CheckBox controls, use `set_addon_checkbox` with an explicit JSON boolean `checked`, optional `expectedChecked`, and `dryRun` first. `click_addon_element` refuses checkbox-only dispatch because it does not update component state. A checked consent box does not authorize or perform the subsequent dialog confirmation; verify the outcome separately. See [checkboxes.md](../../../../docs/checkboxes.md).
